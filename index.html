An Intelligent Chatbot Built for Action

An agentic AI application that combines tool calling, persistent conversations, web search, weather information, calculations, and question answering over uploaded PDFs through Retrieval-Augmented Generation.

View on GitHub ↗ Explore Architecture

Core Features

A modular AI application designed to combine language models, external tools, persistent state, and knowledge retrieval.

🧠

Agentic Workflow

LangGraph decides when a tool is needed, routes the call, processes the result, and returns it to the chatbot for the final answer.

🛠️

Tool Integration

Registered tools handle calculations, Tavily web search, OpenWeather queries, and knowledge base search.

📄

PDF Knowledge Base

Upload a PDF in the Streamlit sidebar. The backend extracts its text, splits it into overlapping chunks, and stores them in Pinecone.

🔎

RAG and Semantic Search

Relevant document chunks are retrieved from Pinecone and used as context for document-based answers.

🧬

Integrated Embeddings

Pinecone's integrated embedding model embeds and searches document text, so no separate embedding service is needed.

💾

Conversation Persistence

PostgreSQL-backed LangGraph checkpointing preserves conversation state so chats can be restored later.

⚡

Streaming Responses

The chat interface shows response progress and tool activity as the agent works.

🗂️

Conversation Management

Create new chats, view and switch between previous conversations, and delete them with confirmation.

🔌

REST API

FastAPI exposes chat, streaming, conversation management, and PDF upload endpoints, with interactive docs at /docs.

How It Works

From user input to an AI-generated response.

STEP 01

Submit a Question

The user sends a question through the Streamlit chat interface.

STEP 02

Process with the Agent

FastAPI identifies the conversation by its thread ID and passes the request to LangGraph, which invokes the chatbot node.

STEP 03

Execute Tools if Needed

The Tool Node runs the selected tool, such as knowledge base search against Pinecone, and returns the result to the chatbot.

STEP 04

Return the Response

The response node prepares the final answer for the frontend, while PostgreSQL checkpoints preserve state.

Backend API

The FastAPI backend exposes endpoints for chat, conversation management, and document ingestion.

GET /health Check backend availability
POST / Submit a standard chat request
POST /tangi Stream chat events
GET /conversations List saved conversations
POST /conversations Create a conversation
GET /conversations/{thread_id}/history Retrieve conversation history
DELETE /conversations/{thread_id} Delete a conversation
POST /documents/upload Upload and ingest a PDF

Run the backend locally and visit http://127.0.0.1:8000/docs to inspect and test the API endpoints.

Run It Locally

Requires Python 3.12 (or a compatible version), uv, a PostgreSQL database, and API keys for the services you plan to use.

1Clone and install

git clone https://github.com/ThimiraDon/agentic-chatbot.git
cd agentic-chatbot
uv sync

2Configure environment variables

Create a .env file in the project root. Never commit it to GitHub. 

GROQ_API_KEY=your_groq_api_key
TAVILY_API_KEY=your_tavily_api_key
OPENWEATHER_API_KEY=your_openweather_api_key
DATABASE_URL=your_postgresql_connection_string
PINECONE_API_KEY=your_pinecone_api_key
PINECONE_INDEX_NAME=agentic-chatbot-vectors

3Start the backend

The API runs at http://127.0.0.1:8000. 

uv run uvicorn src.backend_fastapi:app --reload

4Start the frontend

In a second terminal. Streamlit usually opens at http://localhost:8501. 

uv run streamlit run frontend.py

Limitations and Roadmap

The project is built for local development, with clear next steps toward production readiness.

Current Limitations

  • Uploaded PDFs share one Pinecone namespace rather than being isolated by user or conversation.
  • Retrieval depends on the contents of the configured Pinecone index.
  • External services may impose quotas, rate limits, or costs.
  • Deployment and security hardening are needed before public production use.

Future Improvements

  • Source citations for document-grounded answers.
  • Document deletion, replacement, and metadata filtering.
  • User authentication and per-user document isolation.
  • Better error handling, retries, and rate-limit management.
  • Observability, latency tracking, and retrieval evaluation.
